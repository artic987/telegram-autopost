# Поздравления и автоответ

Работает на GitHub Actions, компьютер и VPS не нужны. `personal.yml` проверяет
Telegram каждый час на 37-й минуте; GitHub может задержать или пропустить запуск.
Используются существующие `TG_API_ID`, `TG_API_HASH`, `TG_STRING_SESSION`.
Общий concurrency `telegram-autopost` исключает одновременную работу с рекламой.
Основной workflow, группы и тексты объявлений не изменены.

## Автоответ только @addvk39

Включён при первом запуске. Реагирует только на новые сообщения после активации,
только от точного аккаунта @addvk39. Числовой ID закрепляется при первом разрешении
username. Если username перейдёт другому аккаунту, отправка остановится.
Другим контактам автоответ не отправляется, даже если для них добавлен день рождения.
Если последнее сообщение исходящее, автоответ не нужен. Если входящее старше суток,
оно пропускается. Не чаще одного автоответа в сутки. Проверяется и прочитанная переписка;
скрипт сам не отмечает сообщения прочитанными.

Текст по умолчанию:
> Автоответ Артура: сейчас я не могу регулярно заходить в Telegram. Пиши сюда, прочитаю, когда появится возможность.

Команды отправляйте в **своё «Избранное»**, каждую отдельным сообщением.
Они применяются при следующем запуске (не мгновенно):

- `/helper off` — выключить автоответ.
- `/helper on` — включить только для @addvk39, не для всех контактов.
- `/away Новый текст` — изменить автоответ.
- `/helper status` — получить настройки и список дат.
- `/greeting {name}, с днём рождения! Артур.` — изменить общий шаблон поздравления.

## Поздравления

Добавьте реальный username и дату, например заменив значения в команде:

`/birthday @username 09.08 Имя`

Реальный список именинников изначально пуст: даты пользователя не предоставлены.
Telegram проверит username и сохранит числовой ID. Максимум 100 получателей.
Одинаковый ID обновляет существующую запись. Числовой ID вместо username возможен,
если текущая сессия способна его разрешить; надёжнее использовать username.

`/forget @username` — удалить дату. `/helper off` выключает только автоответ;
чтобы отменить поздравление, удалите соответствующую дату.

Поздравления отправляются в личку с 10:00 до конца дня по Москве, один раз за год.
Первая штатная проверка после 10:00 — около 10:37. Пропущенные дни не догоняются;
29 февраля отмечается только в високосные годы. После поздравления именинник
виден в списке дат в «Избранном»; отдельное уведомление об успешной отправке не создаётся.

## Состояние и ограничения

В «Избранном» создаётся файл `personal-helper-state.json` с подписью
`#arthur_personal_helper_state_v1`. Его нельзя удалять или редактировать вручную:
там настройки, даты, отметки отправки и закреплённый ID автоответчика.
Файл обновляется на каждом запуске, в публичный репозиторий и артефакты Actions
эти сведения не записываются. Удаление состояния сбрасывает защиту от повторов.
Не запускайте другую копию помощника с той же сессией вне этого workflow.

Отправка резервируется в состоянии заранее. При сбое между записью и доставкой
сообщение может быть пропущено до следующего периода; это предотвращает повторную
отправку при неоднозначном результате Telegram. За запуск не более 30 отправок.
После ограничения Telegram обработка прекращается; сохраняется пауза, если Telegram
позволяет обновить файл состояния. Если запись паузы также ограничена, следующий
запуск может снова получить FloodWait. Это не круглосуточный обработчик сообщений.

GitHub отключает расписания публичных репозиториев после 60 дней без активности
репозитория. Для длительной работы близкому человеку потребуется следить за Actions,
поддерживать проект активным и при необходимости включать расписание снова.
Сам факт успешных почасовых запусков не является гарантией продления активности.
https://docs.github.com/actions/managing-workflow-runs/disabling-and-enabling-a-workflow

## Проверка

`python -m unittest discover -s tests -v`

Тесты проверяют единственного адресата, смену владельца username, выключение,
повторный запуск, даты и сохранение отметки поздравления. Реальное подключение
проверяется выполнением `Telegram Personal Helper` в Actions. При первой установке
push новых файлов запускает workflow. Прочие запуски — расписание и Run workflow.
